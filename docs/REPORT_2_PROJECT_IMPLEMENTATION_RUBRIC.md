# Project Report 2: Project Implementation Rubric

This file records the marking criteria and mandatory content for the Project Implementation report. Treat it as an authoritative requirement when planning, drafting, reviewing, or revising Report 2.

## Mark Distribution

| Section | Marks | Required content |
| --- | ---: | --- |
| Introduction to the Problem | 5 | Reintroduce the project, motivation, and techniques from the Requirements and Specifications Report. Provide enough context for the report to stand alone, but do not copy the earlier report directly or repeat its full level of detail. |
| Overview of the Project and Methodology | 10 | Explain what the team did and which methods and techniques produced the results reported later. Do not present results in this section. Describe the nature of the public dataset used. If the team collected any data, also explain the collection setup. |
| Project Management and Team Work | 5 | Explain how the team collaborated and divided the work. Include a table showing each member's contribution to the overall project. |

## Required Report Structure

1. Introduction to the Problem
2. Overview of the Project and Methodology
3. Project Management and Team Work
4. Results
5. Discussion and Challenges
6. Conclusion
7. References
8. Appendix with Code

Section names may be refined for readability, but every marked component must remain easy for a marker to locate.

## Section Boundaries

- The introduction must be a concise, self-contained recap rather than a copy of Report 1.
- The methodology must describe the dataset, preprocessing, HOG/SVM, Custom CNN, MobileNetV3-Small, evaluation protocol, and reproducibility controls without reporting performance values.
- Performance values, confusion matrices, comparisons, robustness findings, and runtime observations belong in Results.
- Interpretation of why results occurred, limitations, deviations from the initial plan, lessons, and future work belong in Discussion and Challenges.
- Team contribution claims must be specific and consistent with the contribution table.
- The appendix should contain project-created code or carefully selected core excerpts. Do not use an unstructured source-code dump as a substitute for explanation in the main report.

## Mandatory Questions to Answer

### Overview and Methodology

- What did the team do to obtain the reported results?
- Which methods and techniques were used?
- What was the nature of the publicly available dataset?
- If any data were collected by the team, what experimental setup was used?

For this project, PlantVillage is a public dataset; therefore, the report must describe its source, controlled image conditions, selected four-class tomato subset, class balance, train/validation/test construction, and relevant limitations. Do not imply that the team collected the PlantVillage images.

### Discussion and Challenges

- Were the initial project goals achieved? Why or why not?
- Which challenges occurred?
- How did the team change or adjust the plan in response?
- What future work would be appropriate?
- What did the team learn about tomato leaf classification and the compared techniques?
